# 教务请求保护与调度

2026-10-11。仅适用于湖南工学院云端，不改动湘潭理工版本或桌面教务客户端。

## 实施参数与边界

- API 登录验证与 worker 查询共用跨进程请求锁，教务并发 1，请求起点间隔至少 3 秒；等待队列最多 15 秒，忙时明确提示稍后再试。
- 每次学校请求连接超时 6 秒、读取超时 12 秒；当前查询一旦出现网络或响应异常，停止该次查询，不自动重试登录。
- HTTP 429 遵守 Retry-After，至少暂停 15 分钟；HTTP 403 暂停 1 小时；连续三次网络/服务失败暂停 15 分钟。暂停状态落库，重启不能绕过。正常响应重置连续失败计数。
- 不轮换 IP、不自动解验证码、不承诺校方不会风控。密码或验证码异常要求用户重新授权。
- 成绩每天北京时间 08:30、13:30、21:30 三批查询，按账号稳定错峰 0～15 分钟；首次和新学期只建立基线。
- 06:00、19:00 开始错峰预取课表，07:00 当天、20:00 次日按队列发送。课表缓存仅属于当前账号，绑定用户名和学期、获取时间，有效期 18 小时；推送标记数据时间。过期、跨账号或未知学期缓存不用来推送。
- 推送窗口最多 45 分钟。预取未完成时不在推送阶段临时集中查询，而是记录未发送；下一预取批次再查。用户需接受课表快照可能延迟反映调课。
- 队列繁忙/限流的预取和成绩查询，只在原批次窗口内安全延后；已提交或投递结果不明的通知不自动重发。暂停与删除仍在每次发送前检查。
- 不新增自动扩容。人数超过批次处理能力时，明确记录未完成，不靠增加请求速度追赶；运营上应小范围开放，并争取校方授权。

## 验收目标

1. 使用假时钟和假 HTTP 验证请求间隔、跨实例串行、队列超时、429 日期/秒数、403、连续失败和重启后冷却。
2. 验证网络异常不会变成重复登录或重复请求；API 登录与 worker 均经过同一入口。
3. 验证三次成绩时段、账号错峰、预取与发送隔离、缓存时效及归属；原有暂停、去重、账号加密隔离测试继续通过。
4. 本地和服务器运行测试，不对真实教务压测，不自动发送用户消息。
5. 备份并更新云端代码、官网说明；停 worker 后切换代码，保留数据库/密钥/账号设置，检查服务与请求保护状态。
6. 中文分步提交，推送 GitHub 默认分支；下载安装包仍走自有服务器。

## 桌面旧任务迁移补丁（3.0.2）

- 本机发现两个启用的旧任务，均指向仍为 2.1.5 的程序，具有重复查询/推送风险；已由用户明确授权后以管理员权限停用，未删除任务或旧配置。
- 新版检查 ClassPush_HNIT、ClassPush 及根目录，兼容两代课表/成绩任务名。带 HNIT 标识的任务直接停用；通用名称必须确认其可执行文件为当前本校应用，或旧程序携带本校数据目录标记，否则仅提醒人工核对，避免误改其他学校。
- 所有任务只停用、不删除；缺失任务正常跳过，访问被拒绝明确提示管理员处理。对于更早且无法确认学校的程序，不猜测归属。
- 用本机真实 COM 接口验证错误包装：读取内层系统错误码区分任务不存在与访问被拒绝，避免每次启动误报。
- 此保护只覆盖云端 API/worker，不能限制用户电脑上的旧版本或独立网页请求。云端开启前应处理旧任务。
