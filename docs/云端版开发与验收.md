# ClassPush 3.0 本校云端版开发与验收

## 1. 范围与产品约定

仅支持湖南工学院。湘潭理工学院独立目录不参与本次修改。

桌面版保留教务登录、课表、成绩查询、官网更新；删除本地定时推送入口和执行链路。启动时停用本校旧计划任务，防止重复通知。日历导出独立成页，不依赖 WxPusher UID。桌面“云端推送”打开官网的同一管理页面，手机也可直接访问；不维护两套账号管理表单。

云端提供两个独立开关：北京时间 07:00 推送当天课表、20:00 推送次日课表。按队列顺序发送，不能承诺所有人同一秒收到；仅在当次批次后 45 分钟内补偿执行，不发送几小时前的过期提醒。新启用的开关从下一批次生效。成绩每小时检查一次，首次开启仅建立基线，以后推送新增/变化成绩。暂停立即阻止尚未发送的通知；已交给 WxPusher 的通知不能撤回。

用户可查看最近任务、测试推送、暂停/恢复、修改密码和删除云端资料。离线电脑不影响云端任务。教务密码失效时停用该账号任务，并在管理页提示重新授权；不无限循环尝试登录。不承诺永久免登录，也不绕过学校验证码或风控。

## 2. 架构

静态官网 HTML/CSS/JS 保留；新增 `/cloud.html` 手机管理页。Nginx 把 `/api/cloud/` 代理给仅监听 `127.0.0.1:8765` 的 Python Flask API。独立 systemd worker 扫描任务。复用现有本校教务协议、课表解析、学期日期和成绩比较逻辑，不共享桌面的 ConfigManager 文件。

采用 SQLite（WAL）服务少量本校同学，无 Redis、无多租户通用平台。API 与 worker 同机使用数据库；按账号文件锁串行处理发送、修改和删除，防止用户暂停成功后又启动新发送。锁内网络调用必须设置超时。

每账号独立的凭据、教务 token、课程缓存、成绩基线全部加密为数据库密文。AES-GCM 主密钥和 WxPusher AppToken 只来自服务器环境文件，权限 600，不提交 Git，不打进桌面安装包。HTTPS 必须可用。备份必须同时保护数据库和密钥，删除功能清除在线资料，历史备份需按管理员保留周期到期销毁。

## 3. 认证与接口

新设备登录步骤：填写学号、教务密码、UID并同意云端托管 → 服务端验证教务登录 → 给 UID 发一次性验证码 → 输入验证码获得管理会话。现有账号的验证码只发到已绑定 UID，不接受通过填写另一个 UID 改绑。换 UID 需先在旧账号管理中删除再重新绑定。

验证码有效期 5 分钟，最多尝试 5 次；请求按 IP、学号和 UID 限流。会话使用随机高强度 token 的 HttpOnly、Secure、SameSite=Strict cookie，数据库只保存其哈希，30 天到期。修改接口必须同源并携带 JSON；绝不以学号或 UID 作为管理凭证。账号密码不回传浏览器；日志不得输出密码、token、验证码、完整教务请求 URL。

| 接口 | 行为 |
| --- | --- |
| POST `/api/cloud/auth/request` | 验证教务并发送登录验证码 |
| POST `/api/cloud/auth/confirm` | 确认验证码，创建/恢复会话 |
| POST `/api/cloud/auth/logout` | 注销会话 |
| GET `/api/cloud/account` | 开关、状态、最近任务，不含凭据 |
| PATCH `/api/cloud/account` | 修改早/晚/成绩开关、暂停状态 |
| POST `/api/cloud/account/password` | 验证并更新教务密码 |
| POST `/api/cloud/account/test` | 发送一条测试通知 |
| DELETE `/api/cloud/account` | 撤销会话、删除账号及缓存/任务 |

## 4. 数据与调度

accounts 保存账号 id、学号、UID、加密 state、开关、暂停、需重新授权状态、启用时间。sessions 保存 token 哈希与到期时间。challenges 保存验证码哈希、加密待绑定资料与到期/尝试次数。jobs 以账号+日期+批次唯一，保存状态与安全错误摘要。rate_limits 存限流计数。

所有任务明确携带目标日期，不能从本地 push_time 反推。课表日期使用学校学期元数据；2026-2027-1 第二周周一为 2026-09-07，第一周基准为 2026-08-31，缺失日期不猜。未开学展示全部课程；云端非教学期不发送过期课表。缓存必须同时校验账号和学期。

发送前再次读取开关和账号状态。唯一任务键防止重启后重复派发。远端超时无法确定是否投递时，记录“结果待确认”，不自动重复发送。worker 崩溃中断的发送同样标记待确认。不能把 HTTP 200 当作推送成功，必须检查 WxPusher 业务响应。

## 5. 桌面与日历

导航：总览、课表、成绩、日历导出、云端推送、设置、关于。本地登录只需学号与密码。日历导出复用 ICS 生成器，支持全学期/本周/未来7天；显示当前学期、第一周周一与课时，避免旧缓存导出错误日期。提醒可设，未确定学期日期时禁止导出并说明原因。

图文教程分 iPhone、安卓及 Outlook，强调 ICS 是快照，调课后需重新导入且先删除旧日历避免重复。教程给出独立日历建议，支持回到日历页直接导出。

## 6. 迁移与发布

移除晨间、晚间、成绩 GitHub Actions 及其 runner，保留测试 CI。删除 README 中 Fork/Secrets 推送说明。官网首页、下载页、FAQ、版本清单和软件版本统一 3.0.0。安装器仍为中文可选位置 Inno Setup。旧云端绑定不会从桌面静默上传，必须由用户明确同意。

部署先备份官网和现有 version.json；新后端启动、反代和 HTTPS 验证成功后再发布入口。下载包和更新流量继续走自有服务器。服务器未连通时只交付可部署文件，不声称线上发布完成。

## 7. 自动化验收

1. API：非法输入、同源保护、验证码过期/错误/限流、错误 UID 不能夺取既有账号、未认证不可读写、退出/删除会话失效。
2. 隔离：两账号不同凭据、课表、成绩基线；数据库中检索不到测试明文密码和教务 token。
3. 调度：北京时区、早晚目标日期、唯一任务去重、暂停/删除、新启用不补发旧批次、发送超时不重试。
4. 业务：首次成绩不群发历史；学期切换不复用旧课表；周二课程与周一日期映射正确；已知第二周日期测试通过。
5. UI：桌面生产构建通过，手机宽度 375px 可操作，无 token 输入框、无本地定时推送开关；独立 ICS 可导出。
6. 发布：中文安装包构建、启动检查；服务器 API 健康检查、认证及真实教务/微信端到端测试分别记录。

## 8. 最终人工验收

用户只需在真实页面登录一次：验证本地课表/成绩、导出并导入手机日历、手机绑定云端、测试推送、早晚各一个真实批次、暂停和删除。真实密码/验证码由用户在页面输入，不在聊天或文档提供。自动化使用假教务与假推送，不能替代真实学校和微信验收。
